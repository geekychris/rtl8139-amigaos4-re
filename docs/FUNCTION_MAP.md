# rtl8139.device — Function Map

Reconstruction target: `/Users/chris/tmp_bsd/rtl8139.device` (69 720 bytes, `.text` = 0x9430 bytes, VMA 0x1000074–0x10094a4). Disassembly source: `/Users/chris/tmp_bsd/rtl.asm` (9 491 lines).

## How functions were identified

1. **Prologue scan** — grepped every `stwu r1,-N(r1)` in `.text`; 68 hits, each a non-leaf entry.
2. **`bl` targets** — 39 distinct branch-and-link targets, all coincident with the prologue set except two leaf trampolines (`0x10005ac`, `0x10005c0`) which are listed in the AutoInit `FuncTable` at rodata 0x100a0b0 — recovered by inspecting that table.
3. **Vtable-offset decoding** — parsed the exact `struct ExecIFace` and `struct PCIDevice` layouts from `/Users/chris/code/claude_world/refs/os4-sdk/base/Include/include_h/interfaces/exec.h` and `.../interfaces/expansion.h`. Method calls appear as `lwz r9,44(rX)` (loads IExec at driver-base+44), followed by `lwz r9,N(r9); mtctr r9; bctrl` — where `N` maps to a named IExec method. Same pattern with `+48` for the PCIExpansion iface or `unit[164]` for the per-unit PCIDevice iface.
4. **Register tracking** — a small linear-scan analyzer follows `lwz` / `mr` propagation to disambiguate exec-vs-pci method calls.
5. **String cross-refs** — `lis rX,257; addi rX,rX,-N` constructs a rodata address (base 0x1010000 minus N). String pointers (0x100a0e0 = `"rtl8139.device"`, 0x100a144 = `"main"`, 0x100a154 = `"newmemory.resource"`, 0x100a4c0 = `"timer.device"`) confirm library-open / find-task / open-device sites.
6. **AutoInit table** at `rodata 0x100a0b0` yielded the canonical device dispatch order — `Obtain, Release, ?, ?, Open=0x1000864, Close=0x1000704, Expunge=0x10004e8, ?, BeginIO=0x10005d4, AbortIO=0x100007c`.

**Patterns noticed**
- Almost every function is compiled `-O2`, uses r30/r31 for saved base pointers, and follows the AmigaOS4 IFace-call idiom above.
- `unit` layout (per-unit struct, allocated in DevOpen): `+56`=device-base, `+164`=PCIDevice, `+192`=PCI BAR, `+56+X`=MsgPorts/Semaphores (paired), `+220..+235`=multicast filter, `+228..+235`=6-byte MAC (8-byte aligned), `+164`=IPCIDevice iface.
- Ten functions in the 0x1001a60–0x1001f3c cluster are neither `bl`-called nor absolute-referenced anywhere in the binary. They match the SANA-II command-handler shape (small, take r3=IORequest, tail-call into `0x1003354` reply helper). They are most likely stripped-callable helpers left over from a shared source file — recorded here as **DEAD/UNUSED** but included for completeness.
- Two ISR trampolines (`0x10037b0`, `0x10037d4`) exist to adapt the OS4 `AddIntServer` calling convention (`r5 = isData`) to the internal handler’s `r3 = unit` convention — the actual work lives at `0x1007534` (quick top-half) and `0x100868c` (full ISR bottom-half).

## Register conventions used below
- **iexec** = interface at driver-base + 44
- **ipci-exp** = PCIExpansion iface at driver-base + 48
- **ipci-dev** = per-unit PCIDevice iface at unit + 164
- **BAR** = unit + 192 (PCI IO base, e.g. RTL8139 register file)

## Notes and follow-ups

- The **AutoInit table** at `rodata 0x100a0b0` is the ground-truth for the exported device vectors: only Obtain / Release / Open / Close / Expunge / (reserved) / BeginIO / AbortIO are library-visible. Everything else is internal.
- The 10 “DEAD/UNUSED” functions (0x1001a60–0x1001f3c, 0x100120c, 0x10012a0, 0x1001664, 0x100186c, 0x1001988) have no direct callers, no absolute-pointer references anywhere in the ELF, and no `lis+addi` PC-relative constructions of their addresses. They are almost certainly leftover from a single source file that shared logic with the live CmdDispatch (0x10021f4). Recommend leaving them out of the reconstructed C source unless dynamic testing reveals a table that stores them.
- The **wire-type / command validation table** at rodata `0x100a000..0x100a028` (u16 array terminated by 0xffff) is consulted by DevBeginIO and must be faithfully reproduced.
- The `.rodata` **PCI vendor:device ID table** at `0x100a370..0x100a3c0` is a 16-entry array of `(u16 vendor, u16 device)` pairs. First entry `10ec:8139` — canonical RTL8139. Others include Realtek variants and re-badged clones. The table drives DevOpen’s PCI match.
- **ISR discipline**: the top-half handler (0x1007534) does the minimum — mask IMR, ack IRQ line — and returns. The bottom-half (0x100868c) is scheduled via the second trampoline (0x10037d4) — likely a `SoftInt` scheduled from 0x1007534 via `IExec.Cause(344)` that isn’t visible in the top-half itself. Verify during reimplementation.
- **Little-endian register access**: I did not see explicit `lwbrx`/`stwbrx`; instead the driver uses `PCIDevice.InLong/OutLong` etc. which the OS4 PCI stack byte-swaps for you. Preserve that when reimplementing.
